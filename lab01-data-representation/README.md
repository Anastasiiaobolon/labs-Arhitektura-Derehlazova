# Lab 1. Представлення даних у пам'яті комп'ютера

**Середовище:** GitHub Codespaces, Ubuntu, GCC, x86-64.
Усі програми компілюються командою `gcc -Wall -Wextra program.c -o program`.

## Файли

| Файл | Призначення |

| `types.c` | розміри типів C (`sizeof`) |
| `representations.c` | число в decimal / hex / binary |

## Завдання 1. Розміри типів (`types.c`)

```bash
gcc -Wall -Wextra types.c -o types && ./types
```

| Тип | Розмір, bytes | Розмір, bits |
|---|---|---|
| char | 1 | 8 |
| short | 2 | 16 |
| int | 4 | 32 |
| long | 8 | 64 |
| long long | 8 | 64 |
| float | 4 | 32 |
| double | 8 | 64 |
| void * | 8 | 64 |

- **Чи всі типи займають однакову кількість пам'яті?** Ні, від 1 байта (`char`) до 8 байтів (`long`, `double`, вказівник).
- **Скільки бітів займає `int`?** 32 біти (4 байти).
- **Який розмір має `void *`?** 8 байтів.
- **Що це говорить про архітектуру?** Вказівник 64-бітний, тобто середовище 64-бітне (x86-64): адреса пам'яті записується в 64 бітах.

## Завдання 2. Decimal → Hexadecimal → Binary (`representations.c`)

| Decimal | Hexadecimal | Binary |
|---|---|---|
| 10 | 0xA | 1010 |
| 65 | 0x41 | 1000001 |
| 127 | 0x7F | 1111111 |
| 255 | 0xFF | 11111111 |
| 256 | 0x100 | 100000000 |
| 1024 | 0x400 | 10000000000 |

**Чому `65`, `0x41` і `01000001` — це одне й те саме значення?** У пам'яті зберігається лише послідовність бітів. Decimal, hex та binary — різні способи записати одне число для людини: `65 = 6·10 + 5`, `0x41 = 4·16 + 1`, `01000001 = 2^6 + 2^0`. Усі три записи дають значення 65.

## Завдання 3. Виведення бітів (`binary.c`)

Перевірені значення: 0, 1, 10, 65, 127, 128, 255. Наприклад, для 65: `Decimal: 65`, `Hex: 0x41`, `Binary: 01000001`.

**Чому перевірка починається з біта 7, а не з біта 0?** Біт 7 — старший, і в запису числа старші розряди пишуть першими (зліва). Якби цикл ішов від біта 0, ми б вивели біти в зворотному порядку, і число прочиталося б задом наперед.

## Завдання 4. Символ — це також число (`characters.c`)

| Character | Decimal | Hex |
|---|---|---|
| A | 65 | 0x41 |
| B | 66 | 0x42 |
| a | 97 | 0x61 |
| 0 | 48 | 0x30 |
| 9 | 57 | 0x39 |

**Що зберігається в `char c = 'A';`?** Числове значення 65 (код ASCII). Літеру «A» ми бачимо лише тому, що `printf("%c")` інтерпретує це число як символ. Символ `'0'` має код 48, тобто це не число 0.

## Завдання 5. Signed та unsigned (`signed_unsigned.c`)

**Прогноз:** для `-1` у `int8_t` очікую бітове представлення `11111111` (two's complement).

**Результат:**
```text
int8_t  signed_value   = -1
uint8_t unsigned_value = 255
signed_value   hex: 0xFF, binary: 11111111
unsigned_value hex: 0xFF, binary: 11111111
Same bits? yes
```

**Як `11111111` може бути і 255, і -1?** Біти однакові, відрізняється **інтерпретація**. Для `uint8_t` усі 8 бітів дають число 255. Для `int8_t` (two's complement) старший біт має вагу −128, тому `11111111 = −128 + 127 = −1`. Значення визначається типом.

## Завдання 6. Межа `unsigned` (`overflow.c`)

**Прогноз:** `255 + 1` у `uint8_t` дасть `0`, бо 256 не вміщується у 8 бітів.

**Результат:**
```text
Before: value = 255
After value++: value = 0
254     -> 254
255     -> 255
255 + 1 -> 0
255 + 2 -> 1
```

**Пояснення:** `uint8_t` має 8 бітів, тобто значення 0..255 (2^8 = 256 варіантів). Результат обчислюється за модулем 256: `256 mod 256 = 0`, `257 mod 256 = 1`. Для беззнакових типів така поведінка визначена стандартом C. Для **знакових** типів переповнення в C є undefined behavior, тому переносити цей результат на `signed` не можна.

## Завдання 7–8. Байти в пам'яті та endianness (`memory.c`, `endian.c`)

**Гіпотеза (до запуску):** очікую варіант B: `78 56 34 12` (little-endian, як у x86-64).

**Результат `memory.c`:**
```text
value  = 0x12345678
byte 0 = 0x78
byte 1 = 0x56
byte 2 = 0x34
byte 3 = 0x12
```

**Результат `endian.c`** (адреси у вас будуть іншими):
```text
value = 0x12345678

Address              Value
0x7ffd3b9adac8       0x78
0x7ffd3b9adac9       0x56
0x7ffd3b9adaca       0x34
0x7ffd3b9adacb       0x12

Byte order: Little-endian

- **У якому напрямку змінюються адреси?** Зростають: кожен наступний байт має адресу на 1 більшу.
- **Який байт за найменшою адресою?** `0x78`, наймолодший байт числа.
- **Чому це little-endian?** У little-endian першим (за меншою адресою) записується наймолодший байт.
- **Чи змінилося саме число?** Ні. Значення завжди `0x12345678`, змінюється лише порядок розташування його байтів у пам'яті.

## Завдання 9. Один набір бітів — різні інтерпретації

| Інтерпретація | Значення |
|---|---|
| Binary | 01000001 |
| Hexadecimal | 0x41 |
| Unsigned decimal | 65 |
| ASCII character | A |

**Чому комп'ютеру недостатньо знати лише біти?** Біти самі по собі не мають змісту. Значення визначає **тип**, тобто **інтерпретація** в певному **контексті**: ті самі `01000001` можуть бути числом 65, символом `A` або частиною іншого типу. Тому програма має знати, як саме читати ці біти.

## Підсумкове завдання (`inspect.c`)

```bash
gcc -Wall -Wextra inspect.c -o inspect && ./inspect
```
```text
Enter value (0-255): 65
Decimal:      65
Hexadecimal:  0x41
Binary:       01000001
Character:    A

Value: 0x12345678
Size: 4 bytes
Memory:
byte 0: 0x78

byte 2: 0x34

```

Порядок байтів програма **визначає під час виконання** (перевіряє, що лежить за найменшою адресою), а не друкує готовий текст.

## Відповіді на контрольні питання

- **Біт і байт.** Біт — найменша одиниця інформації (0 або 1). Байт — 8 бітів.
- **Скільки значень у n бітів?** 2^n.
- **Діапазон 8-бітного unsigned:** 0..255.
- **Діапазон 8-бітного signed (two's complement):** −128..127.
- **Чому hex зручний?** Одна hex-цифра = рівно 4 біти, тому байт це 2 цифри. Запис короткий і легко переводиться в біти.
- **`11111111` як `uint8_t` та `int8_t`:** 255 та −1.
- **`uint8_t` 255 після збільшення:** стає 0 (wraparound за модулем 256).
- **Що зберігається для символу `A`:** число 65 (код ASCII), тобто біти `01000001`.
- **Endianness:** порядок, у якому байти багатобайтового числа розташовані в пам'яті.
- **Порядок байтів на x86-64:** little-endian.
- **`sizeof(int)`:** розмір типу `int` у байтах (у нашому середовищі 4).
- **Чому ті самі біти — різні дані?** Бо значення визначається типом та контекстом інтерпретації.

## Висновок

Експериментально встановлено: типи мають різний розмір (`int` — 4 байти, вказівник — 8 байтів, середовище 64-бітне); decimal, hex і binary лише різні записи одного значення; символ у пам'яті — це число; біти `11111111` означають 255 або −1 залежно від типу; `uint8_t` при переповненні переходить від 255 до 0; система x86-64 використовує little-endian.
